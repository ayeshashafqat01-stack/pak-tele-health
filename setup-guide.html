Pak-Tele-Health — Setup Guide

Everything you need to clone, set up, and run the project from scratch.

All data in this project is synthetic. No real patient information. This is a development MVP.
Using Claude? You can paste any section of this guide to Claude and ask it to help you run the commands or troubleshoot issues. The project has a CLAUDE_BUILD_PROMPT.md with full context.

npm install --legacy-peer-deps
The --legacy-peer-deps flag is needed because some packages have peer dependency conflicts. This is safe to use.

This installs ~350 packages including Next.js, Prisma, NextAuth, Tailwind CSS, etc. It may take 2-5 minutes.

After install, generate the Prisma client:

npx prisma generate
4
Set Up MySQL Database

You have 3 options. Pick the one that works for your setup:

Option A: Local MySQL with root access (simplest)

If MySQL is installed and you can access it as root:

# Start MySQL if not running
sudo service mysql start

# Login as root and create the database
sudo mysql -u root

In the MySQL prompt, run:

-- Create the database
CREATE DATABASE pak_tele_health CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- Create a dedicated user (recommended)
CREATE USER 'pth_app'@'localhost' IDENTIFIED BY 'pth_dev_pass';
GRANT ALL PRIVILEGES ON pak_tele_health.* TO 'pth_app'@'localhost';
FLUSH PRIVILEGES;

EXIT;

Option B: Docker (no local MySQL needed)

If you have Docker installed, the project includes a docker-compose.yml:

docker compose up -d mysql

# Wait ~10 seconds for MySQL to start, then verify:
docker compose exec mysql mysql -u root -ppth_root_pass -e "SELECT 1"

Docker creates everything automatically: database, user, password.

Option C: MySQL without root/sudo (WSL, shared server)

If you can't use sudo (e.g., WSL without admin):

# Initialize a local MySQL data directory
mkdir -p /tmp/pth-mysql /tmp/pth-mysql-log
mysqld --initialize-insecure --datadir=/tmp/pth-mysql \
  --log-error=/tmp/pth-mysql-log/error.log

# Start MySQL with local data (no root needed)
mysqld --datadir=/tmp/pth-mysql \
  --socket=/tmp/mysql.sock \
  --port=3306 \
  --log-error=/tmp/pth-mysql-log/error.log \
  --skip-grant-tables \
  --default-time-zone='+00:00' \
  --character-set-server=utf8mb4 \
  --collation-server=utf8mb4_unicode_ci &

# Wait 3 seconds, then create the database
sleep 3
mysql -u root --socket=/tmp/mysql.sock -e \
  "CREATE DATABASE IF NOT EXISTS pak_tele_health CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
Tip: With Option C, MySQL stops when you close the terminal. Run the mysqld ... command again to restart it next time.
5
Configure Environment Variables

Copy the example env file:

cp .env.example .env

Now edit .env and set the DATABASE_URL based on which MySQL option you used:

If you used Option A (local MySQL with user):

DATABASE_URL="mysql://pth_app:pth_dev_pass@localhost:3306/pak_tele_health"

If you used Option B (Docker):

DATABASE_URL="mysql://pth_app:pth_dev_pass@localhost:3306/pak_tele_health"

If you used Option C (local data dir with socket):

DATABASE_URL="mysql://root@localhost:3306/pak_tele_health?socket=/tmp/mysql.sock"

If you used sudo mysql (root with no password):

DATABASE_URL="mysql://root@localhost:3306/pak_tele_health"

The other settings in .env can stay as defaults:

# Keep these as-is for development
AUTH_SECRET="dev-secret-do-not-use-in-production-change-me-32chars"
NEXTAUTH_URL="http://localhost:3000"
NODE_ENV="development"
ALLOW_SEED="true"

Troubleshooting

❌ "Can't connect to MySQL server"

MySQL isn't running. Start it:

# Linux
sudo service mysql start

# macOS
brew services start mysql

# Docker
docker compose up -d mysql

❌ "Access denied for user"

Your DATABASE_URL in .env has wrong credentials. Check:

  • Username and password match what you created in Step 4
  • Database pak_tele_health exists
  • Try connecting manually: mysql -u YOUR_USER -pYOUR_PASSWORD pak_tele_health

❌ "npm install" fails with native addon errors

The @node-rs/argon2 package uses prebuilt binaries. If it fails:

npm cache clean --force
rm -rf node_modules package-lock.json
npm install --legacy-peer-deps

❌ "prisma db push" fails

Check your DATABASE_URL in .env. Common issues:

  • MySQL not running
  • Database doesn't exist (create it first with Step 4)
  • Wrong socket path (if using Option C)

❌ Seed fails with "SEED BLOCKED"

Add ALLOW_SEED="true" to your .env file.

❌ Login doesn't work / "Invalid email or password"

Seed might not have run. Run it again:

npx tsx prisma/seed.ts

Then try logging in with hw@demo.pth / demo-hw-pass.

❌ Styles look broken / unstyled page

PostCSS plugin might be missing. Reinstall:

npm install --legacy-peer-deps

Make sure postcss.config.mjs exists with @tailwindcss/postcss plugin.

❌ Port 3000 already in use

# Kill whatever is using port 3000
fuser -k 3000/tcp    # Linux
lsof -ti:3000 | xargs kill  # macOS

# Or start on a different port
npm run dev -- --port 3001

❌ "Module not found" errors

npx prisma generate
npm run dev

Reset Everything (Start Fresh)

If something goes wrong and you want a clean slate:

# Drop all tables and recreate
npx prisma db push --force-reset

# Re-seed
npx tsx prisma/seed.ts

# Restart
npm run dev
⚠️ --force-reset deletes ALL data. Only use in development.
